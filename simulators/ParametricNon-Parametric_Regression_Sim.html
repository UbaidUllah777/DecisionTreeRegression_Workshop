The one idea to hold on to

Parametric models pick a formula first (a parabola, an exponential) and use data to tune a fixed number of knobs. Ten points or ten million, the model is still a handful of numbers.

Non-parametric models skip the formula. The data itself defines the shape, so the model grows with the data: a tree adds branches, KNN keeps every point.

"Non-parametric" does not mean "no parameters". It means the number of parameters is not fixed in advance.

Analogy. Parametric = a recipe card ("2 cups flour, 1 egg"). Non-parametric = a photo album of every cake you have baked; to predict a new cake you look up the most similar ones.

Section 1

Meet the family

Regression predicts a number (a price, a temperature, a score) from inputs. Every regression model is a function f(x) that we choose so its predictions ŷ = f(x) land close to the real y. The four models below disagree on what f is allowed to look like.

Parametric→ Linear→ Polynomial

Polynomial regression

Definition. Polynomial regression models y as a polynomial of degree d in x. It adds powers of x as new features and then fits an ordinary linear regression on them.

ŷ = w0 + w1x + w2x2 + … + wdxd

Why is it under "Linear"? The curve bends, but the model is linear in its parameters w. Each w multiplies a fixed feature (1, x, x², …), so the same Ordinary Least Squares solution used for a straight line still works. Simple linear regression is just degree 1.

Knob you choose: degree d. Knobs the data tunes: d + 1 weights.

How it learns: minimize the mean squared error. There is a closed-form answer (OLS / normal equation), or you can walk downhill with gradient descent.

Parametric→ Non-linear→ Exponential

Exponential regression

Definition. Exponential regression models quantities that change by a constant percentage per unit of x: growth when b > 0, decay when b < 0.

ŷ = a · eb·xa = starting value, b = growth/decay rate

Why is it "Non-linear"? The parameter b sits inside the exponent, so ŷ is not a weighted sum of fixed features. No single matrix formula solves it directly; you need an iterative optimizer (Gauss–Newton, Levenberg–Marquardt or gradient descent).

The log trick. Taking logs gives ln ŷ = ln a + b·x, a straight line. Fitting that line with OLS is fast and makes a good starting guess, but it minimizes error in log-space, which gives small values more weight than big ones.

Doubling time / half-life = ln 2 / |b|. Two parameters, very interpretable.

Non-parametric→ Decision Tree

Decision tree regression

Definition. A regression tree splits the x-axis into regions with yes/no questions ("is hour ≤ 6.5?") and predicts the average y of the training points in each region. The prediction is a staircase.

ŷ(x) = mean of yi in the leaf where x lands

How it learns (CART). At each node, try every possible threshold and keep the one that lowers the squared error the most. Repeat inside each half until you hit max_depth or a leaf gets too small. This is a greedy search, not a formula.

Why non-parametric? The number of splits is decided by the data. More data and deeper trees mean more leaves, with no fixed formula.

Knobs you choose: max_depth, min_samples_leaf.

Non-parametric→ KNN🌸 from the KNN Workshop

K-Nearest Neighbours

Definition. KNN is a simple, non-parametric, instance-based method used for both classification and regression. To predict for a new data point, it finds the k training points closest to it and lets them decide:

  • Classification: the new point gets the majority label of its k neighbours.
  • Regression: the prediction is the average value of its k neighbours.
ŷ(x) = (1/k) Σi ∈ Nk(x) yiregression: average
ŷ(x) = most common label in Nk(x)classification: vote

How it learns. It doesn't, at least not up front. KNN is a lazy learner: fit() just stores the training data, and the work happens at prediction time.

Two design choices drive performance: the value of k, and how features are scaled, because distances drive the algorithm. Distance is usually Euclidean, √(Δx₁² + Δx₂²), or Manhattan, |Δx₁| + |Δx₂|.

Small k follows every local quirk, noise included (high variance). Large k averages over a wide area and blurs the boundaries (high bias). Cross-validation picks k.

Section 5.1 · Connection

  
Cross-validation: choosing the knob honestly

  

    

      
The problem. Every model on our tree has a knob you set before training: polynomial degree, tree max_depth, KNN k, and for the exponential the fit method. If you pick the knob that scores best on the training data, you will always pick the most complex model, because it memorizes the noise.

      
Cross-validation is a resampling procedure that estimates how well a model generalizes to unseen data. Split the data into K folds, train on K−1 of them, test on the one left out, rotate, and average the K test errors.

      
    
        
  • Holdout: one train/test split. Fast, but the score depends on which points landed in the test set.
    • 
        
  • K-Fold: every point is tested exactly once. The standard choice (K = 5 or 10).
    • 
        
  • Stratified K-Fold: keeps class proportions equal in each fold (used for classification; for regression you can bin y).
    • 
        
  • LOOCV: K = n. Almost no waste, but n model fits. Cheap for KNN, expensive for deep learning.
    • 
      

    

    

      
Watch K-fold rotate

      

      

      
      
● test fold   ● training folds. Each fold gets its own model; the score is the average of the fold errors.

Different loss, different winner

    

      
MSE (squared error)
L = (1/n) Σ (yi − ŷi)²
Smooth bowl with one minimum; OLS solves it exactly. Squares punish big misses, so one outlier can drag the whole line.

      
MAE (absolute error)
L = (1/n) Σ |yi − ŷi|
Robust to outliers (it targets the median). Has kinks, so no normal equation; needs iterative or linear-programming solvers.

      
Huber
squared if |r| ≤ δ, linear beyond
The compromise: smooth like MSE near the minimum, robust like MAE for outliers. Available as HuberRegressor in scikit-learn.

Section 5.3 · Connection

  
Ordinary Least Squares: the one-shot answer

  

    

      
Stack the data into a matrix. With n data points and p features:

      
y = Xβ + ε

      
OLS picks the β that minimizes the sum of squared errors

      
S(β) = Σi (yi − Σj Xijβj)² = ‖y − Xβ‖²

      
Set the gradient of S to zero and solve. The result is the normal equation:

      
β̂ = (XᵀX)−1 Xᵀy

      
This is what sklearn.linear_model.LinearRegression computes (in practice through a numerically safer least-squares solver rather than an explicit inverse).

      
Polynomial link. For polynomial regression the columns of X are just 1, x, x², …, xd (a Vandermonde matrix). Same formula, more columns.

    

    

      
Step through the normal equation

      

      
      

      

      

    

  


  

    
Why scaling matters: the condition number

    
XᵀX must be inverted. When its columns (x, x², x³ …) are nearly parallel or wildly different in size, the inverse amplifies tiny rounding errors. The condition number measures that amplification. Compare raw speeds (20–130 km/h) with standardized ones.

    
Log scale. Above ~10¹⁵ double-precision numbers lose all accuracy. This is why the Lab code puts StandardScaler() before PolynomialFeatures.

  


  

    
OLS beyond straight lines

    

      
Exponential: OLS after a log
ln y = ln a + b·x is linear, so OLS on (x, ln y) gives a and b in one shot. Caveat: it minimizes squared error of logs, so it under-weights large y values. Use it as a starting point, then refine with non-linear least squares.

      
Decision tree: OLS in every leaf
If a model is just a constant c, the c that minimizes Σ(y − c)² is the mean. That is exactly the value a tree puts in each leaf. Every leaf is a tiny intercept-only OLS fit.

      
KNN: a local mean
KNN's prediction, the plain average of k neighbours, is also the least-squares constant for those k points. With weights="distance" it becomes a weighted least-squares constant. No global matrix to invert.

Section 5.4 · Connection

  
Gradient descent: walking downhill

  

    

      
When there is no closed-form answer (exponential regression, neural networks) or X is too big to invert, we iterate:

      
    
        
  1. Start with random weights.
    2. 
        
  2. Compute the gradient of the loss with respect to the weights.
    3. 
        
  3. Step against it: w ← w − η · ∇L(w)
    4. 
        
  4. Repeat until the gradient is near zero or you hit the iteration limit.
    5. 
      

      
For a line ŷ = w₀ + w₁x with MSE loss the gradients are

      
∂L/∂w₀ = −(2/n) Σ (y − ŷ)    ∂L/∂w₁ = −(2/n) Σ (y − ŷ)·x

      
Learning rate η is the step size. Too small: thousands of tiny steps. Too large: you overshoot and bounce up the other wall, or explode.

    

    

      
Variants

      
Batch GD uses all n points per step: smooth path, slow per step on big data.
Stochastic GD (SGD) uses 1 random point: noisy zig-zag, very cheap steps.
Mini-batch uses a small batch (32, 64…): the default in deep learning.

      
Challenges

      
Local minima: stuck in a dip that is not the lowest. MSE for linear models is a single bowl, so this cannot happen here, but it does for neural nets.
Saddle points: flat in one direction, so progress crawls.
Vanishing / exploding gradients: steps become tiny or huge. Unscaled features cause a version of this: try turning off standardization below.
